# راهنمای افزودن منبع قیمت جدید (Price Source) و قرارداد یکپارچه ادپتورها

در RealRate تمامی منابع قیمت بر اساس اصل **تنها مرجع حقیقت (Single Source of Truth)** به صورت ساختاریافته (Code-First) تعریف و مدیریت می‌شوند.

---

## ۱. ساختار کانفیگ سورس در `sources.config.js`

برای افزودن یک منبع جدید، کافی است آن را به آرایه `PRICE_SOURCES_CONFIG` در فایل [`api/src/config/sources.config.js`](../api/src/config/sources.config.js) اضافه کنید:

```javascript
// api/src/config/sources.config.js
export const PRICE_SOURCES_CONFIG = [
  {
    id: "src_def_my_source",
    name: "نام رسمی سورس (مثال: صندوق‌های سرمایه‌گذاری کاریزما)",
    brand: "کاریزما",               // برند کوتاه سورس جهت نمایش در پرانتز نام آیتم‌ها
    priceType: "my_source_type",
    sourceType: "api_url",          // یا "telegram", "forex_api", "bourse_symbols", "charisma_funds", ...
    endpoint: "https://api.example.com/rates",
    category: "bourse_fund",        // دسته‌بندی از روی categories.config.js
    unit: "واحد",                   // واحد شمارش دارایی (تومان، گرم، عدد، برگ سهم، واحد، دلار، تتر)
    isFund: true,                   // آیا ماهیت صندوق یا طرح دارد؟
    fetchIntervalSec: 300,          // دوره پولینگ به ثانیه (دست‌کم ۳۰۰)
    // اختیاری: واحد مظنه‌ی سورس — "toman" (پیش‌فرض)، "rial"، "usd"، "usd_cross"
    // quote: "usd",
    // اختیاری: برای کاتالوگ، بازاری که شناسه‌ها به آن تعلق دارند ("bourse" → "bourse__<نماد>")
    // market: "bourse",
    // اختیاری — محافظ قیمت نامعقول و قدیمی شدن:
    // maxJumpPct: 25,              // بیشترین تغییر بین دو دریافت (٪)؛ بیشتر از این تا تکرار نشود پذیرفته نمی‌شود
    // confirmTicks: 3,             // چند دریافت پشت‌سرهم تا جهش واقعی پذیرفته شود
    // staleAfterSec: 1800,         // پس از این مدت بدون دریافت موفق، قیمت «قدیمی» علامت می‌خورد
    // اختیاری: آنچه سورس می‌دهد (پایین‌تر، «نوع سورس»)
    // outputs: "multi",            // چند قلم با شناسه‌ی خودشان (فید)
    // isCatalog: true,             // فهرست کامل یک بازار (با `market`)
    isActive: true,
    isPrimary: false,
    displayConfig: { showOnHomePage: true },
  },
];
```

> [!NOTE]
> **تفکیک مسئولیت متادیتا (قاعده معماری):**
> فیلدهای `badge`، `badgeColor` و `iconName` دیگر روی سطح سورس تعریف نمی‌شوند؛ این فیلدها مستقیماً و به صورت خودکار از دسته‌بندی مرجع در [`categories.config.js`](../api/src/config/categories.config.js) استخراج می‌شوند تا هیچ‌گونه دوگانگی یا Drift در داده‌ها رخ ندهد.

### نوع سورس

آنچه یک سورس می‌دهد فقط از کانفیگش خوانده می‌شود (`domain/priceSources.js`، `sourceKindOf`):

| نوع | کانفیگ | مثال | اقلام |
|---|---|---|---|
| تک‌نرخی | هیچ‌کدام | دلار آزاد، طلای ۱۸ | یکی، با `priceType` سورس |
| چندخروجی | `outputs: "multi"` | ارزهای جهانی (فارکس)، سری‌های tgju | چند قلم، هر کدام با شناسه‌ی خودش |
| کاتالوگ | `isCatalog: true` و `market` | نمادهای بورس، صندوق‌های مفید و کاریزما | فهرست کامل یک بازار، شناسه `${market}__${symbol}` |

فهرست کاتالوگ **با فهرست قبلی‌اش ادغام می‌شود** (`mergeCatalogItems`): نمادی که در یک دریافت نباشد یا بی‌قیمت بیاید، آخرین قیمتش را نگه می‌دارد؛ پس پاسخ ناقص هیچ‌وقت بازاری را خالی نمی‌کند.

هر چه سورس لازم دارد در کانفیگ خودش است، نه در آداپتر: آدرس، `jsonPath`/`regex` (api_url)، `series` (tgju)، `metaEndpoint` و `symbolMap` (صندوق‌های کاریزما: نام انگلیسی ← نماد بورسی) و `knownItems` (نام و واحد قلمی که فقط شناسه‌اش معلوم است، مثل طرح‌های کاریزما). سورس api_url‌ای که `jsonPath` به جوابش نرسد می‌تواند `customParser(data, src)` داشته باشد که یک عدد برگرداند.

### دوره‌ی دریافت و وضعیت

- **دوره:** `fetchIntervalSec` (دست‌کم ۵ دقیقه یعنی ۳۰۰ ثانیه، که پیش‌فرض هم هست). زمان‌بند هر دقیقه اجرا می‌شود و هر سورسی را که نوبتش رسیده می‌گیرد: یک دوره پس از **آخرین تلاش، موفق یا ناموفق** — پس سورس خراب هم تا دوره‌ی بعدش صبر می‌کند و هر دقیقه به وب‌سرویس فشار نمی‌آورد.
- **کهنه:** پس از `staleAfterSec` (پیش‌فرض: ۵ دوره، دست‌کم ۳۰ دقیقه) بدون دریافت موفق.
- **وضعیت** (`sourceScheduleOf`): `off` (خاموش)، `pending` (هنوز دریافت نشده)، `error` (آخرین تلاش خطا داد؛ خطای خود وب‌سرویس نگه داشته می‌شود)، `stale` (کهنه) یا `ok` (سالم).

در پنل مدیریت فقط می‌توان سورس را خاموش کرد یا سورس اصلی شناسه‌اش کرد (در D1، کلید `price_source_overrides`)؛ سورس آنجا ساخته یا حذف نمی‌شود.

## ۱.۱ دارایی‌های دلاری (انس، نفت، رمزارز)

دارایی‌ای که در بازار خودش به دلار قیمت می‌خورد (انس طلا، نقره، پلاتین و پالادیوم، نفت برنت و WTI، بیت‌کوین، اتریوم) فقط با `quote: "usd"` در کانفیگ سورس تعریف می‌شود — هیچ شرطی روی شناسه لازم نیست:

```javascript
{ id: "src_def_oil_brent", priceType: "oil_brent", quote: "usd", unit: "بشکه", category: "commodity", ... }
```

- **یک شناسه برای هر دارایی:** انس طلا همیشه `ons_gold` است؛ «انس تومانی» و «انس دلاری» دو دارایی جدا نیستند، دو نمایش از یک دارایی‌اند.
- **قیمت تومانی مثل همیشه:** `price` آیتم دفتر قیمت به تومان است (قیمت دلاری × دلار خود دفتر)؛ پورتفو، تراکنش‌ها و ارزش کل به تومان می‌مانند و هیچ داده‌ی ذخیره‌شده‌ای عوض نمی‌شود.
- **قیمت خود دارایی:** آیتم `currency: "usd"` و `priceUsd` (قیمت دلاری، تا سنت) دارد؛ کارت‌ها، جستجو و پورتفو قیمت را به دلار نشان می‌دهند و معادل تومانی زیرش (`web/src/features/market/assetPrice.js`). آیتم بدون `currency` تومانی است (`currencyOf`).
- **دامنه‌ی روز و درصد تغییر** به دلار حساب می‌شوند (`params.dayCurrency: "usd"`) — انس با بالا رفتن دلار «رشد» نمی‌کند.
- **تاریخچه:** بسته‌ی تومانی زیر شناسه و بسته‌ی دلاری زیر `<id>@usd` (`usdSeriesKey`) ثبت می‌شود؛ نمودار کارت از سری دلاری خوانده می‌شود. پاک‌کردن «شناسه‌های بی‌صاحب» در پنل این کلیدها را نگه می‌دارد و بک‌فیل tgju با واحد دلار هر دو را پر می‌کند.
- مشخصات دارایی (نام، واحد، نام‌های جستجو) در `api/src/domain/specs/` است؛ کالاهای جهانی در `commodity.spec.js` و دسته‌ی `commodity` («کالا»).

## ۱.۲ سری‌های tgju و شاخص‌هایی که دارایی نیستند

- **سورس tgju** (`sourceType: "tgju_indicators"`): هر سری tgju (`tgju.org/profile/<slug>`) با یک شناسه در `series` تعریف می‌شود و آخرین مقدار جدول روزانه‌اش خوانده می‌شود (`services/market/tgju.client.js`، همان خواننده‌ی بک‌فیل تاریخچه). واحد با `quote` سورس است (tgju معمولاً ریال). سری‌ای که خطا بدهد کنار می‌ماند و بقیه به‌روز می‌شوند:

```javascript
// طلا، سکه و حباب سکه: یک سورس چندخروجی؛ نام، دسته و واحد هر قلم از مشخصه‌ی (spec) خودش است
{ id: "src_def_tgju", sourceType: "tgju_indicators", quote: "rial", outputs: "multi",
  series: [
    { slug: "geram18", id: "gold_18k" }, { slug: "sekee", id: "full_coin" }, ...
    // حباب اختلاف دو قیمت است و درصدی خیلی بیشتر از قیمت تکان می‌خورد: محافظ جهش خودش را دارد
    { slug: "coin_blubber", id: "bubble_full_coin", maxJumpPct: 100 }, ...
  ] }
```

هر سری یک درخواست است (موازی، در همان اجرای زمان‌بند). خروجی‌ای که در `series` حد جهش (`maxJumpPct`) خودش را دارد، با همان حد سنجیده می‌شود و بقیه با حد سورس (`guardOf` در `domain/priceSources.js`).

- **دسته‌ی غیرقابل نگهداری:** دسته‌ای با `holdable: false` در `categories.config.js` (مثل `bubble`) روی کارت‌ها و نمودارها هست ولی در پورتفو و جستجوی خرید نیست (`isHoldableCategory`).
- **شاخصِ یک دارایی دیگر:** مشخصه‌ای با `bubbleOf` (مثل `bubble.spec.js`) درصدش از ارزش آن دارایی بدون خودش را در `params.bubblePct` می‌گیرد.
- برای تاریخچه‌ی گذشته، همان slug را با `suggest` به `config/tgjuCatalog.js` اضافه کنید تا در پنل تاریخچه قابل انتخاب باشد.

## ۲. قرارداد نهایی ادپتورها (Universal Adapter Contract)

هر ادپتور سورس (خواه در `api/src/services/market/sources/` یا به عنوان ادپتور سفارشی) **بدون استثنا** باید قرارداد استاندارد زیر را رعایت کند:

### ساختار اینترفیس `ISourceAdapter`:
آداپتر فقط یک نوع وب‌سرویس را می‌شناسد و نه چیز دیگر. با `sourceType` سورس انتخاب می‌شود (`sources/index.js`؛ نوع ناشناخته آداپتر ندارد و همگام‌سازی همین را گزارش می‌کند) و بین دو فراخوانی چیزی به خاطر نمی‌سپارد.
1. `id`: همان `sourceType` که پوشش می‌دهد (مانند `telegram`, `api_url`, `forex_api`).
2. `name`: نام فارسی (در صفحه‌ی مدیریت دیده می‌شود).
3. `fetchRaw(sourceConfig, env?)`: خواندن وب‌سرویس؛ درخواست ناموفق با پیامی که مدیر بفهمد **خطا پرتاب می‌کند** (مثل `پاسخ وب‌سرویس بورس: 503`) — همین پیام در صفحه‌ی مدیریت نشان داده می‌شود.
4. `parse(raw, sourceConfig)`: تبدیل جواب به ساختار استاندارد؛ اگر قیمتی در جواب نباشد خطا پرتاب می‌کند.

آداپتر هیچ‌وقت چیزی ذخیره، کش یا ادغام نمی‌کند، داده‌ی ذخیره‌شده نمی‌خواند و آدرس، شناسه یا نماد پیش‌فرض ندارد؛ بقیه‌ی کار را خط لوله برای همه‌ی سورس‌ها یکسان انجام می‌دهد. استخراج اقلامش یک تابع خالص export‌شده است (مثل `bourseItemsOf`، `charismaFundItemsOf`) که جدا تست می‌شود.

### ساختار الزامی خروجی `parse()`:
```javascript
{
  items: [
    {
      id: "item_key", // نماد یا کد خود آیتم؛ پیشوند بازار را دفتر قیمت اضافه می‌کند
      name: "نام پاکسازی‌شده آیتم",
      price: 154200 // قیمت به واحد مظنه‌ی سورس (quote)؛ تبدیل و گرد کردن کار دفتر قیمت است
    }
  ],
  datetime: "2026-09-21T10:00:00.000Z" // رشته معتبر ISO 8601
}
```

> [!IMPORTANT]
> **قاعده اقلام تک‌نرخی و چندنرخی:**
> حتی سورس‌های تک‌مقداری (مانند دلار آزاد، طلای ۱۸ عیار، سکه امامی) نیز خروجی `parse` را در قالب آرایه یک‌عضوی `items: [{ id, name, price }]` برمی‌گردانند.

## ۳. قرارداد شناسه‌ها (Universal ID Contract)

شناسه نام دارایی است، نه سورس: فولاد همیشه همان فولاد است، از هر سورسی که بیاید.
برای اقلام کاتالوگ: `${market}__${symbol}` که `market` در کانفیگ سورس تعیین می‌شود.

- **مثال‌ها:**
  - `bourse__فولاد` (نماد فولاد، از هر سورسی)
  - `bourse__اهرم` و `bourse__عیار` (صندوق‌های قابل معامله: همان شناسه بورس)
  - `charisma_plan__gold` (طرح طلای کاریزما)
  - `usd`، `usdt`، `gold_18k` (سورس‌های تک‌نرخی: priceType)
- اگر دو سورس یک شناسه را بدهند، اولی (سورس اصلی، به ترتیب کانفیگ) همان شناسه را می‌گیرد و نسخه بقیه `${sourceId}__${id}` می‌شود.
- شناسه‌ها یک شکل دارند: حروف کوچک، ي/ك عربی به ی/ک، ارقام فارسی به 0–9، بدون نیم‌فاصله.

## ۴. موتور مرکزی نمایش (Display Engine)

هیچ بخشی از فرانت‌اند یا لایه روت‌ها نباید نام سورس یا واحد را به صورت دستی یا شرط‌های `if / switch` رندر کند. تمام فرآیند نمایش از طریق [`displayEngine.js`](../api/src/domain/displayEngine.js) (که در فرانت‌اند نیز به صورت `web/src/config/displayEngine.js` در دسترس است) انجام می‌شود:

```javascript
import {
  getItemDisplayName, // قالب‌بندی استاندارد "{نام آیتم} ({نام سورس})"
  getItemUnit,        // استخراج واحد اندازه‌گیری از کانفیگ سورس
  getItemCategory,    // استخراج دسته‌بندی معتبر از کانفیگ سورس
  getItemBadge,       // استخراج بج فارسی از categories.config.js
  getCategoryColor,   // استخراج رنگ بصری بج (amber, emerald, indigo, ...)
  getCategoryIconName,// استخراج نام آیکون Lucide (Award, Coins, TrendingUp, ...)
  getSourceBrand,     // استخراج برند سورس (بورس، کاریزما، مفید، tgju...)
} from "../config/displayEngine.js";

// مثال کاربرد:
const displayName = getItemDisplayName({ id: "bourse__فولاد", name: "فولاد مبارکه" });
// خروجی: "فولاد مبارکه (بورس)"

const unit = getItemUnit("gold_18k");
// خروجی: "گرم"

const category = getItemCategory("src_def_charisma__اهرم") // شناسه قدیمی هم خوانده می‌شود;
// خروجی: "bourse_fund"

const badge = getItemBadge("src_def_charisma__اهرم");
// خروجی: "صندوق"
```

## ۵. جریان ذخیره‌سازی و ارکستراسیون یکپارچه

```
Cloudflare Cron Trigger (هر دقیقه)
  └─ syncAllSources(env)                       sourceSync.service.js
       ├─ فقط سورس‌هایی که نوبتشان رسیده (isSourceDue: یک دوره پس از آخرین تلاش)
       ├─ یک درخواست برای هر آدرس مشترک بین چند سورس
       ├─ fetchRaw() → parse() → { items, datetime }
       ├─ کاتالوگ: mergeCatalogItems(قبلی، تازه)
       ├─ guardSourceItems(): جهش نامعقول تا تکرار نشود نگه داشته می‌شود
       ├─ saveSourceItems(): source_items:<id>، فقط وقتی عوض شده باشد
       ├─ دفتر قیمت ("prices"، با syncedAt / failedAt / error هر سورس)
       └─ تاریخچه‌ی قیمت
```

سورسی که خطا بدهد آخرین قیمت‌هایش را در دفتر نگه می‌دارد؛ خطا و زمانش زیر `sources` دفتر ثبت می‌شود.

## ۶. صفحه‌ی سورس‌های قیمت در پنل مدیریت

`/admin/sources` (`web/src/features/admin/components/AdminPriceSourcesPage.jsx`) همه‌ی سورس‌ها را در دو گروه — «سورس‌های نرخ پایه (طلا، ارز، سکه)» (تک‌نرخی) و «هاب سورس‌های چند خروجی و فیدها» (چندخروجی و کاتالوگ) — با خلاصه‌ی وضعیت نشان می‌دهد. برای هر سورس: وضعیت و آخرین خطا، دوره‌ی دریافت («هر ۵ دقیقه»)، آخرین دریافت موفق، دریافت بعدی، زمان کهنه شدن، واحد مظنه، نوع، آداپتر، دسته و واحد، محافظ جهش، آدرس یا سری‌های tgju و آنچه داده (قیمتش، یا تعداد اقلام و پیش‌نمایش سه قلم). کارها: روشن/خاموش، مرجع کردن (فقط جایی که چند سورس یک شناسه را می‌دهند)، **تست** (اجرای آزمایشی: همین حالا خوانده و پارس می‌شود، چیزی ذخیره نمی‌شود)، **دریافت الان** (از کل خط لوله) و **همه‌ی اقلام** (فهرست ذخیره‌شده‌ی فید، با جستجو). ردیف‌ها را سرور می‌سازد (`services/market/priceSourcesAdmin.service.js`)؛ هزاران قلم یک کاتالوگ فقط وقتی خواسته شود فرستاده می‌شود.

با این معماری، افزودن هر سورس جدید به سیستم تنها با اضافه کردن رکورد آن در `sources.config.js` انجام شده و کلیه بخش‌های پولینگ، کش، پایگاه‌داده، API کاتالوگ و UI بدون نیاز به هیچ کد اضافی فوراً با آن هماهنگ می‌گردند.
