# پیامک‌های بانک — استاندارد قالب و افزودن بانک جدید

پیامک تراکنش بانک (برداشت یا واریز) به یک تراکنش استاندارد تبدیل می‌شود تا به‌عنوان هزینه (برداشت) یا درآمد (واریز) ثبت شود. اپ اندروید پیامک‌ها را خودکار می‌خواند؛ همه‌چیز روی خود گوشی انجام می‌شود و متن پیامک به سرور فرستاده نمی‌شود.

| فایل | چیست |
|---|---|
| `api/src/domain/bankSms.js` | موتور: یکسان‌سازی متن، اجرای قالب‌ها، تبدیل تاریخ و مبلغ، تطبیق حساب. درباره‌ی هیچ بانکی چیزی نمی‌داند |
| `api/src/domain/bankSmsTemplates.js` | داده: قالب پیامک هر بانک. **برای افزودن بانک فقط همین فایل تغییر می‌کند** |
| `api/tests/unit/bankSms.test.js` | نمونه پیامک‌های واقعی هر بانک (`SAMPLES`) |
| `web/src/shared/native/smsInbox.js` | اپ اندروید: خواندن پیامک‌های فرستنده‌های بانک (`senders`) از صندوق گوشی — `docs/ANDROID.md` |

هر دو ماژول با symlink در `web/src/utils/` هم هستند (مثل بقیه‌ی ماژول‌های domain).

## خواندن یک پیامک

1. **یکسان‌سازی** (`normalizeSmsText`): ارقام فارسی/عربی → انگلیسی، «ي/ك» → «ی/ک»، حذف نویسه‌های نامرئی جهت (RLM و ...)، «٬» → «,»، هر خط trim و خطوط خالی حذف؛ خطوط با `\n` به هم وصل می‌شوند.
2. **انتخاب بانک**: اگر فرستنده معلوم باشد (اپ اندروید)، قالب‌های بانکی که `senders` آن شامل فرستنده است؛ وگرنه همه‌ی بانک‌ها.
3. **قالب‌ها به ترتیب** امتحان می‌شوند؛ اولین `pattern` که کل متن را بپذیرد برنده است.
4. **گروه‌های نام‌دار** regex به تراکنش تبدیل می‌شوند.

## قالب

```js
{
  bankId: 'parsian',              // شناسه‌ی استاندارد بانک (api/src/config/banks.config.js)
  senders: ['+98...'],            // شماره‌/نام فرستنده (اختیاری؛ برای اپ اندروید)
  templates: [
    {
      id: 'parsian-balance',      // یکتا، با پیشوند bankId
      unit: 'rial',               // واحد مبلغ در پیامک: 'rial' (پیش‌فرض) یا 'toman'
      direction: 'sign',          // جهت تراکنش (پایین)
      pattern: re(String.raw`^...$`),  // روی کل متنِ یکسان‌شده؛ ^ و $ الزامی
    },
  ],
}
```

### گروه‌های نام‌دار

| گروه | الزامی | معنی |
|---|---|---|
| `amount` | ✅ | مبلغ با جداکننده؛ علامت می‌تواند قبل یا بعد باشد (`397,500-`، `-397,500`) |
| `balance` | | مانده پس از تراکنش |
| `account` | | شماره حساب (ارقام، ستاره‌دار هم مجاز)؛ ۴ رقم آخرش برای تطبیق حساب |
| `card` | | شماره کارت (معمولاً ستاره‌دار)؛ ۴ رقم آخرش نگه داشته می‌شود |
| `date` | | تاریخ شمسی: `MM/DD`، `YY/MM/DD` یا `YYYY/MM/DD` (جداکننده `/` `-` `.`). بدون سال: نزدیک‌ترین همان روز تا امروز |
| `time` | | `HH:MM` |
| `kind` | | کلمه‌ی نوع تراکنش (برداشت/واریز/خرید ...) برای `direction` کلمه‌ای |
| `desc` | | متن آزاد (فروشگاه، پایانه ...) |

تکه‌های آماده در `P` همان فایل: `P.amount`، `P.balance`، `P.date`، `P.time`، `P.digits`.

### جهت (`direction`)

- `'sign'` (پیش‌فرض): از علامت مبلغ؛ `-` برداشت، `+` واریز. بدون علامت ← پیامک خوانده نمی‌شود.
- `'debit'` یا `'credit'`: ثابت (قالبی که فقط برای برداشت است).
- `{ debit: ['برداشت', 'خرید'], credit: ['واریز'] }`: از کلمه‌ی گروه `kind`.

### خروجی (`BankSmsTransaction`)

`{ bankId, templateId, direction: 'debit'|'credit', amount /* تومان */, balance /* تومان یا null */, account, accountLast4, cardLast4, date /* میلادی YYYY-MM-DD */, time, description, fingerprint }`

- مبلغ‌ها همیشه **تومان** هستند (ریال ÷ ۱۰).
- `fingerprint`: هش متن یکسان‌شده؛ هزینه‌ی ثبت‌شده آن را در `smsFingerprint` نگه می‌دارد تا یک پیامک دو بار ثبت نشود.
- `matchSmsAccount(tx, accounts)`: حساب کاربر با همان بانک و همان ۴ رقم آخر شماره حساب یا کارت؛ وگرنه اگر فقط یک حساب از آن بانک دارد، همان.

## افزودن بانک جدید

1. چند پیامک واقعی بانک (برداشت، واریز، خرید با کارت ...) را جمع کنید؛ ارقام و نام‌ها را عوض کنید ولی **شکل متن** را دست نزنید.
2. برای هر شکل یک قالب در `bankSmsTemplates.js` بنویسید. مثال — پیامکی مثل:
   ```
   بانک نمونه
   برداشت: 1,250,000
   کارت: 6037***1234
   1405/07/06-14:49
   ```
   ```js
   {
     bankId: 'sample',
     senders: [],
     templates: [{
       id: 'sample-card',
       direction: { debit: ['برداشت', 'خرید'], credit: ['واریز'] },
       pattern: re(String.raw`^بانک نمونه\n(?<kind>برداشت|واریز|خرید)\s?:\s?(?<amount>${P.amount})\nکارت\s?:\s?(?<card>${P.digits})\n(?<date>${P.date})-(?<time>${P.time})$`),
     }],
   }
   ```
3. نمونه‌ها را به `SAMPLES` در `api/tests/unit/bankSms.test.js` اضافه کنید، با فیلدهایی که باید خوانده شوند. تست‌ها بررسی می‌کنند هر بانک دست‌کم یک نمونه دارد، هر قالب `^…$` و گروه `amount` دارد و شناسه‌ها یکتا هستند.
4. `npm test --workspace=api`.

نکته‌ها:
- regex را روی متن **یکسان‌شده** بنویسید (ارقام انگلیسی، بدون فاصله‌ی اضافه، هر خط جدا).
- جای ممکن `\s?` بگذارید (فاصله‌ی دو طرف `:` در گوشی‌های مختلف فرق می‌کند).
- قالب دقیق‌تر را جلوتر بگذارید؛ اولین قالبی که بخورد برنده است.

## بانک‌های پشتیبانی‌شده

| بانک | قالب‌ها |
|---|---|
| پارسیان | فرستنده `PARSIANBANK`؛ `parsian-balance` — شماره حساب، مبلغ با علامت، مانده، تاریخ `MM/DD`، ساعت |
| بلو | فرستنده `+989999987641`؛ `blu-balance` — «برداشت پول / واریز پول» (جهت از کلمه)، مبلغ و موجودی به ریال، ساعت، تاریخ `YYYY.MM.DD` |
